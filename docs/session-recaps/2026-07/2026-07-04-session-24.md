## Key decisions made
- **`Money` → `MoneyEmbeddable` (`@Embeddable`)** rather than two flat columns —
  reused wherever `Money` is persisted. Located in `account.infrastructure`
  **for now** (rule of three); it cannot live in `com.pecunia.shared` (an
  ArchUnit rule forbids JPA there), and staying in `account` long-term would
  couple other contexts to it — so it is promoted to a shared-infra location at
  the second consumer (Block 3 `transaction`), with its own ADR then.
- **`save()` new-vs-existing via `@Version Long` on the aggregate**, not
  `Persistable`. A wrapper `@Version` (null → `persist`, non-null → `merge`)
  removes the phantom insert `SELECT` **and** adds optimistic locking. The
  version is carried on `Account` (open → unversioned, `reconstitute(..., version)`,
  `Optional<Long> version()`) so it survives the two-way-mapping round-trip.
  `Persistable` rejected (its transient flag does not survive an adapter that
  rebuilds the entity); plain `merge`-everywhere kept as the documented fallback.
- **No cross-context FK** `accounts.owner_id → users.id`; a plain indexed `uuid`.
  Contexts share identifiers, not schema-level joins; `owner` is never user
  input, so orphan risk is structurally low.
- **Tenancy enforced by the explicit `owner` parameter in the port**, not
  Hibernate `@TenantId`/`@Filter`; RLS stays post-MVP defense-in-depth per
  ADR-0014.
- **`OpenAccount` double-submit is a web/application idempotency-key concern**,
  deliberately not solved at the persistence layer (no natural key to dedupe on)
  and deferred (likely post-MVP).

## Concepts explained / learned
- **`persist` vs `merge` with application-assigned ids**: a non-null `@Id` makes
  Spring Data route `save()` through `merge()`, which issues a `SELECT` before an
  `INSERT`. The update path is nonetheless cheap: the entity loaded earlier in the
  same `@Transactional` use case is a persistence-context hit, so `merge` needs no
  extra `SELECT` — the phantom read only bites on insert.
- **Why `identity`'s `ON CONFLICT` upsert does not transfer to `account`**: it is
  the shape of the write, not concurrency frequency. `identity` is an idempotent
  find-or-create on a **natural key** `(iss, sub)`; `account` mints a **fresh
  surrogate PK** each time, so there is no "same row" to converge on and no
  conflict to resolve.
- **`@Version` new-entity detection** (wrapper so "unpersisted" is `null`), and why
  it must round-trip through the aggregate in a rebuild-on-map adapter.
- **`@Embeddable` mechanics**: no table of its own, protected no-arg ctor required,
  field access, `@AttributeOverride` to name columns per use; Hibernate 6 maps
  `java.util.Currency` to its ISO code natively (no converter).
- **ArchUnit shared-kernel purity**: `com.pecunia.shared..` forbids Spring/JPA/
  Hibernate/Lombok, which is exactly why a JPA embeddable cannot live in the kernel.
- **PostgreSQL `now()` = transaction-start time**: rows inserted in the same
  transaction share `created_at`, so `OrderByCreatedAtAsc` is only a stable sort
  across separate transactions (fine for the real one-account-per-request flow).

## Issues encountered & resolved
- **Wrong first recommendation (self-corrected).** Initially proposed
  `Persistable`; after research (Arho Huttunen's hexagonal adapter, Vlad Mihalcea
  on assigned ids) recognized it does not survive a rebuild-on-map adapter and
  switched to `@Version` on the aggregate. ADR-0030 rewritten accordingly.
- **`mvn verify` first run errored**: Docker was down, so the schema-validating
  Testcontainers IT could not start (environment, not code). Re-ran with Docker up
  → green.
- **`mvn` from repo root failed** ("no POM in this directory"): used
  `-f apps/api/pom.xml` (no root pom, per project convention).
- **`import lombok.*` wildcard** (IntelliJ "class count to use import with '*'"
  default of 5) → switched to explicit imports; noted the durable IDE setting.
- **`@ToString` on `MoneyEmbeddable`** flagged as an amount-leak vector → removed
  (consistent with `Account.toString()` deliberately omitting monetary fields).
- **`@AllArgsConstructor` vs a DB-managed `createdAt`** → replaced with an explicit
  private constructor omitting `createdAt`.
- **Two `AccountRepository` beans** (stub + adapter) would break the context →
  stub removed.
