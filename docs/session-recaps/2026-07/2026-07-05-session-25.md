## Key decisions made
- **MapStruct for the mapper** (ADR-0024 convention), with `ReportingPolicy.ERROR`.
- **Option 3 for the fluent-accessor problem**: MapStruct handles the inbound
  direction (generated DTO getters -> record), but the outbound `Account -> DTO`
  is hand-written, because the domain's deliberately fluent accessors
  (`account.id()`, not `getId()` — ADR-0013) are not read by MapStruct's default
  `AccessorNamingStrategy`. The canonical fix (a custom SPI) requires a **separate
  module** (verified against the official `mapstruct-examples`, a 2-module setup),
  so it is deferred to the next domain->DTO consumer (rule of three).
- **`@RestControllerAdvice` scoped to `account.web`** (`basePackageClasses`), not
  a global shared advice — deferred until a second advice duplicates the logic.
- **`OpenAccount` returns the `Account` aggregate**, consistent with
  `ListAccounts` returning `List<Account>` (ADR-0027); the web layer maps it to
  the response DTO instead of re-deriving the default status.
- **Money stays scale-4 on the wire** (option A); display precision is a
  currency-driven presentation concern handled by the frontend (Angular
  `CurrencyPipe` / `Intl.NumberFormat`), not by rounding at the DTO boundary.

## Concepts explained / learned
- **MapStruct `AccessorNamingStrategy` SPI**: overriding accessor recognition
  (fluent `property()` vs bean `getProperty()`) must live in a separate JAR with
  a `META-INF/services` registration on the annotation-processor path — there is
  no in-module escape hatch (confirmed via the MapStruct reference + examples).
- **Ports returning domain aggregates**: the hexagonal dependency rule allows
  `web -> domain` (the ArchUnit rules only forbid `web -> infrastructure`);
  *reading* an aggregate to map it is fine, but handing a *mutable* aggregate to
  an adapter is an authority leak (the adapter could call `archive()`).
- **`@WebMvcTest`** without `controllers = X` instantiates *all* controllers;
  `@ControllerAdvice` beans are auto-detected in the slice (no `@Import` needed).
- **`@Valid` on a generated-interface parameter** is honoured on the implementing
  method — proven by the blank-name test returning 400 with no use-case call.
- **Exception-handler specificity**: `AccountAlreadyArchivedException` (a
  `DomainException`) maps to 409 while the `DomainException` catch-all maps to
  400, because Spring selects the most specific handler.
- **Money precision**: store/compute at scale 4 (avoids rounding drift), present
  at the currency's default fraction digits (CHF = 2) on the client.

## Issues encountered & resolved
- **`UriComponentsBuilder` injected as a field** in the controller — not a Spring
  bean, and mutable/stateful; would fail context startup. Replaced with
  `ServletUriComponentsBuilder.fromCurrentRequest().path("/{accountId}")`.
- **Advice initially incomplete** (only the 404 handler) — a thrown
  `DomainException` / `AccountAlreadyArchivedException` would have fallen through
  to 500. Completed with the 409 and 400 handlers.
- **Swagger `@WebMvcTest` regression** — unscoped slices broke on the new
  controller's unsatisfied dependencies; scoped both to `MeController`.
- **Self-correction on the SPI cost**: initially presented the custom
  `AccessorNamingStrategy` as "~a dozen lines in the project"; web verification
  showed it needs a separate build artifact, which shifted the choice to option 3.
