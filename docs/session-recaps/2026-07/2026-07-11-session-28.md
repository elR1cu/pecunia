- **Added the ArchUnit rule** `driving_ports_do_not_return_domain_types`
  (9th rule): driving-port interfaces must not return domain types, generic
  type arguments inspected via `getAllInvolvedRawTypes()`. Validated by

## Key decisions made

- **Owner resolution moves to the application layer** — a web-only guard is
  O(N adapters) and unverifiable by the application; a single resolution
  point via `CurrentUserProvider` closes the IDOR-by-construction hole.
  System-initiated flows (Kafka, batch) will carry the owner in trusted
  internal events; the A (dedicated system ports) vs B (context propagation)
  choice is deferred to the first real consumer.
- **`OpenAccount` mirrors `CreateCategory` strictly** (returns `AccountId`;
  a new `GetAccount` builds the 201 body) — symmetry between contexts and no
  exception to "a command yields metadata, never a read model".
- **`ParentCategoryValidator` is a concrete package-private class, not an
  interface** — interfaces are reserved for ports (boundaries/polymorphism);
  tests exercise the real validator against the mocked repository.
- **Read-model mapping lives in the application layer** (`AccountView.fromAccount`
  static factory) after a review caught services importing the web mapper.

## Concepts explained / learned

- **Trust boundaries for tenancy**: the `owner` is trustworthy only when it
  comes from the authenticated principal or a trusted internal event — never
  from any adapter payload. Application-layer resolution turns a per-adapter
  discipline into a structural guarantee.
- **A driving port is not a REST endpoint**: `GetAccount` was added with a
  single internal consumer (the controller's 201 body) and no OpenAPI change.
- **ArchUnit generics**: `notHaveRawReturnType` alone misses `List<Account>`;
  `JavaType.getAllInvolvedRawTypes()` inspects type arguments. A green rule
  should be mutation-tested to prove it can fail.
- **MapStruct and records**: record accessors are read natively, so read
  models dissolve the fluent-accessor clash that had forced the hand-written
  `AccountMapper.toDto` (Session 25) — no `AccessorNamingStrategy` SPI needed.
