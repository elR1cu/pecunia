## Key decisions made
- **`Intl.NumberFormat` over Angular `CurrencyPipe`** for money display:
  `CurrencyPipe` routes through `DecimalPipe` and loses precision on large
  decimals (angular/angular#23893) — the same float trap the backend avoids by
  serializing amounts as strings — and would need `registerLocaleData('de-CH')`;
  `Intl` is engine-native (ICU), no locale registration.
- **A reusable pure pipe over an inline expression**: money will reappear on the
  dashboard and transaction views (Block 4); the pipe is a single formatting
  source, memoized, with formatters cached per currency.
- **`Number(amount)` at MVP scale**: exact for realistic CHF amounts; a
  string-based formatter would only matter beyond ~1e15 CHF. Noted in code.
- **Left the landing page untouched**: its amounts are static demo text, not
  `Money` values from the API — nothing to format.

## Concepts explained / learned
- **`CurrencyPipe` precision**: its signature accepts `string | number` but
  coerces to a native JS number internally, so a precision-preserving decimal
  string loses precision on large values — confirmed against the angular.dev
  doc and issue #23893.
- **`docker exec` and stdin**: without `-i`, a heredoc is not passed to the
  container process; the first cleanup transaction silently ran on empty input
  (psql hit EOF, no-op) until `-i` was added. `-c` queries were unaffected.
- **Swiss currency formatting via ICU**: `de-CH` renders `CHF 8'000.00`
  (apostrophe grouping) and negatives as `CHF-5'210.35`; asserting against a
  reference `Intl` formatter keeps specs robust across ICU/glyph differences.
