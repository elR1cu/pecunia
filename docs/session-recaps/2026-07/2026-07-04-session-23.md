## Key decisions made
- **Account REST shape** (contract only): soft delete via `DELETE` (AIP-164, not a
  custom verb); `201 + Location + full resource`; `Money {amount, currency}`;
  errors as RFC 9457 `ProblemDetail`. Confirmed **409 (not 412)** for
  already-archived — 412 is for `If-Match`/ETag preconditions.
- **Owner resolution = A2** (ADR-0028): an internal `UserId` (v7) decoupled from
  the IdP, mapped from `(iss, sub)`, over reusing the Keycloak `sub` directly.
- **JIT provisioning at login** via a custom `OidcUserService` (not lazy), with
  the internal `UserId` carried on an enriched principal (`PecuniaOidcUser`).
- **Idempotent provisioning via DB upsert** (ADR-0029, option B): delegates
  atomicity to Postgres (`ON CONFLICT DO NOTHING`), avoiding the app-level
  catch's `rollback-only` trap and index bloat.
- **`CurrentUserProvider` as a shared-kernel port** (adapter in `security`) to
  break the `identity ⇄ security` package cycle — the `IdGenerator` pattern.
- **Non-indexed Redis sessions** for the MVP (indexed / logout-everywhere deferred).
- Validation outside the domain uses `Objects.requireNonNull` (runtime), not
  `@NonNull` jspecify (static-only) nor Jakarta `@Valid` (edge DTOs only).

## Concepts explained / learned
- **AIP-164 soft delete**: `DELETE` marks the row; `Get` still returns it; `List`
  hides it unless `show_deleted`; restore via a custom verb — matches our model.
- **Race condition / TOCTOU**: `find` then `create` is non-atomic; concurrent
  first logins collide on the unique constraint. `ON CONFLICT DO NOTHING` + a
  re-`find` (insert-then-select) is idempotent without a transactional trap.
- **JPA `equals`/`hashCode` with Hibernate proxies**: use `instanceof` (proxies
  subclass the entity) and the **getter** (`getId()`, proxies null their fields),
  not `getClass()` / field access (Vlad Mihalcea).
- **Structured Concurrency (`StructuredTaskScope`) is still preview in Java 25** →
  keep `ExecutorService` (with try-with-resources, `AutoCloseable` since Java 19).
- **`spring.session.redis.namespace` has no effect** (spring-session#3423): the
  autoconfig never calls `setRedisKeyNamespace` on the default `RedisSessionRepository`;
  the annotation / a `SessionRepositoryCustomizer` apply it directly.

## Issues encountered & resolved
- **`identity ⇄ security` cycle** (ArchUnit): `MeController → security` +
  `security → identity`. Fixed by making `CurrentUserProvider` a `shared` port.
- **Testcontainers on Spring Boot 4**: testcontainers BOM pinned (2.0.5,
  `testcontainers-*` artifacts); `spring-boot-starter-data-jpa-test`;
  `@DataJpaTest` moved to `...data.jpa.test.autoconfigure`;
  `@AutoConfigureTestDatabase` replaced by `spring.test.database.replace=none`.
- **`@Modifying` upsert needs a transaction**: the direct-`save` test wrapped in a
  `TransactionTemplate` (the service supplies one in prod).
- **Double bean definition** (`@Component` + `@Bean`) for `PecuniaOidcUserService`,
  and slice tests importing `SecurityConfig` → added `@MockitoBean`.
- **App would not start** (`AccountRepository` has no adapter — application layer
  merged in #22 without infra) → **temporary `StubAccountRepository`** (uncommitted).
- **BFF sessions in memory, not Redis** (missing connection), then **`UserId` not
  Serializable** once the principal was actually persisted — both fixed.
