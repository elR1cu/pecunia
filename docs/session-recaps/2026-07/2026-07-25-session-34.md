# Session Recap — 2026-07-25 — Session 34

## Objective
Prepare Block 8 (Production Deployment) by settling the deployment
platform decisions on paper before writing any code: hosting provider,
IaC tooling, secrets strategy, and a stack simplification surfaced by the
analysis (Redis removal). No code was written; the session produced four
ADRs and the accompanying documentation updates.

## What was done
- **Researched the VPS landscape** (web, July 2026): Hetzner, Infomaniak
  Public Cloud, Exoscale, Scaleway, OVHcloud, plus Azure Switzerland
  North after the author raised it. All serious European providers have
  Terraform/OpenTofu support; the differentiator is provider *quality*
  (first-party vs generic) and price.
- **Settled the data residency requirement**: real financial data must not
  leave Switzerland. Anonymization was examined and rejected (it solves
  "showing data to third parties", not "where data lives", and would
  destroy the app's daily utility). This requirement eliminated Hetzner
  (initially recommended on cost/DX before the constraint was stated) and
  reframed the decision.
- **Chose Infomaniak Public Cloud** (ADR-0035): `a4-ram8-disk50-perf1`
  (4 vCPU / 8 GB / 50 GB, ~€14.50/month from aggregated EUR figures; CHF
  billing and VAT to confirm in the official calculator). Exoscale
  rejected at ~4–5× the cost; Azure rejected for persistent hosting
  (cost + CLOUD Act nuance on "Swiss" data) but retained as an
  **ephemeral AKS interview demo** extending the Block 10 k3d work.
- **Sized the stack**: two JVMs (Spring Boot + Keycloak) drive the budget
  (~2.5–3.5 GB total with PostgreSQL, reverse proxy, OS); 4 GB is too
  tight, 8 GB comfortable. Redis removal does not change the sizing.
- **Chose OpenTofu over Terraform and Pulumi** (ADR-0036), after
  web-verifying that Terraform CLI has no client-side state encryption
  (backend-side only; ephemeral values are complementary, not
  equivalent) while OpenTofu ships it since v1.7 — relevant because the
  IaC state will hold OpenStack credentials and the repo is public.
  Skill reads as "Terraform/OpenTofu" on the CV; migration either way is
  cheap at current divergence.
- **Chose SOPS + age for runtime secrets** (ADR-0037): encrypted dotenv
  files committed to the public repo, age key in password manager +
  GitHub Actions secret, CI decrypts and ships `.env` to the VM.
  Vault/OpenBao explicitly deferred with documented triggers.
- **Decided to remove Redis** (ADR-0038, supersedes ADR-0011): with a
  single app instance the requirement is session *persistence*, which
  `spring-session-jdbc` on the already-present PostgreSQL provides;
  keeping Redis is a permanent carrying cost against a cheap, improbable
  future migration. Implementation deferred to a dedicated PR (paper
  first, per the author's sequencing choice).
- **Settled the availability doctrine**: recoverability over
  availability. All single-VM SPOFs accepted; RPO 24 h (daily encrypted
  off-site backup), RTO < 1 h (VM reconstructible from repo + two keys +
  backup), restore procedure must be *tested*. Demo isolation via a
  `demo` user with fictional data on the same instance (multi-tenancy
  does the work).
- **Updated the docs**: ADR-0035..0038 written, ADR-0011 marked
  superseded, roadmap Block 8/10/11 and Technology Adoption Triggers
  reworked (new Redis-reintroduction and OpenBao trigger sections),
  CLAUDE.md stack lines updated.

## Key decisions made
- **Infomaniak Public Cloud, `a4-ram8-disk50-perf1`** — data residency as
  the deciding constraint; ~2× Hetzner accepted as its price.
- **OpenTofu** — state encryption + open-source coherence at negligible
  CV cost.
- **SOPS + age** — versioned encrypted source of truth; OpenBao deferred
  with triggers.
- **Redis out, `spring-session-jdbc` in** — production shrinks to app +
  PostgreSQL + Keycloak + reverse proxy.
- **Recoverability over availability** — accepted SPOFs with documented
  RPO/RTO instead of HA.
- **Azure = ephemeral demos only** (AKS, fictional data, hourly billing);
  never persistent hosting.
- **Sequencing**: everything on paper first (this session); Redis
  migration PR next, then Block 8 execution.

## Concepts explained / learned
- **Provider API models**: Hetzner/Exoscale expose opinionated high-level
  APIs (~3 resources per VM); OpenStack exposes the explicit IaaS graph
  (~7–8 resources: instance, security group + per-rule resources,
  floating IP + association). The explicit model is the same shape as
  `azurerm`/AWS/GCP — learning it on Infomaniak is direct preparation for
  the Azure demo, so the "OpenStack constraint" is an argument *for*, not
  against.
- **Official Infomaniak Terraform provider covers only KaaS/DBaaS/DNS**
  (verified via the repo's docs/resources listing) — compute still goes
  through `terraform-provider-openstack`. Initial claim corrected
  mid-session.
- **Terraform vs OpenTofu state encryption**: verified that Terraform
  relies entirely on backend-level at-rest encryption; OpenTofu encrypts
  state and plan client-side (AES-GCM, pluggable key providers).
  Terraform's ephemeral values / write-only attributes reduce what
  reaches the state but do not protect what remains.
- **SOPS mechanics**: per-value encryption keeps names readable (useful
  diffs), MAC protects file integrity, `sops edit` avoids plaintext on
  disk; compromised key ⇒ rotate the *secrets* (public Git history keeps
  old ciphertext).
- **SPOF reasoning at small scale**: availability is derived from
  business impact; at single-user scale, buy MTTR (backups, IaC, tested
  restore), not MTBF (HA). Fewer components beat replicated components.
- **Blueprint-inheritance lesson** (from "why was Redis there?"): the
  canonical BFF diagram embeds scale assumptions; every component must be
  justified by a requirement, not by presence in the reference
  architecture. Same test later killed Vault-now and HA-now.
- **Currencies**: session figures mixed EUR (Infomaniak aggregator), USD
  (Exoscale), CHF (billing reality) — flagged; CHF confirmation is a
  pre-provisioning TODO.
